# AutoDeriva Application Specification

## Purpose & Scope
- AutoDeriva automates Windows system setup by discovering hardware, matching it against a curated driver catalog, downloading the required packages from a remote repository, and installing them via `pnputil`. It is optimized for remote/hybrid environments where the repo is not locally cloned.
- Primary entrypoint: `scripts/Install-AutoDeriva.ps1`. A portable launcher `Install-AutoDeriva.bat` bootstraps the PowerShell script (downloading it if needed) and forwards CLI arguments.
- Targets Windows 10/11 with optional post-setup tweaks (taskbar/UI and OneDrive startup) and Wi‑Fi profile cleanup.

## Repository Layout (operationally relevant)
- `scripts/Install-AutoDeriva.ps1` — main orchestrator, includes config handling, downloads, installs, stats, and auxiliary commands (e.g., `-ShowConfig`, `-ExportUnknownDevicesCsv`).
- `Install-AutoDeriva.bat` — downloads or reuses the installer script, strips BOM, and runs it with argument forwarding (prefers Windows PowerShell, falls back to `pwsh`).
- `config.defaults.json` / optional `config.json` — default and local override configuration.
- `exports/driver_inventory.csv` — per-INF metadata + hardware IDs (generated by `scripts/Get-DriverInventory.ps1`).
- `exports/driver_file_manifest.csv` — per-file metadata + SHA256 and INF association (generated by `scripts/Get-DriverFileManifest.ps1`).
- `drivers/` — packaged driver payloads grouped by device models (multiple OEM trees).
- `cuco/CtoolGui.exe` — packaged Cuco utility used for optional deployment.
- `dev-scripts/` — developer tooling (format/lint/test runners, manifest regeneration).
- `tests/` — Pester suites covering CLI help, hashing, CSV export, preflight behaviors, and common paths.
- `logs/` — runtime log output (`autoderiva-*.log`, created on demand).
- `docs/configuration.md` — authoritative config key reference.

## Runtime Flow (Install-AutoDeriva.ps1)
1) **Auto-elevation & console prep**
   - Elevates unless `AUTODERIVA_TEST=1`. Respects `AUTODERIVA_REPOROOT` to relaunch the repo-local script. Sets console colors when possible.
2) **Configuration assembly**
   - Start from internal defaults → merge `config.defaults.json` (local or fetched from GitHub) → merge `config.json` → optional remote overrides (`RemoteConfigUrl` or `-ConfigUrl`) → CLI switches. `SingleDownloadMode` forces `MaxConcurrentDownloads=1`.
   - Flags to exit early: `-ShowConfig`, `-Help`, `-ClearWifiAndExit`, `-DownloadAllAndExit`, `-DownloadCucoAndExit`.
3) **Logging setup**
   - If enabled, writes to `logs/autoderiva-YYYYMMDD-HHMMSS.log` and mirrors to console. Optional cleanup: `-CleanLogs` (force delete), or retention rules (`LogRetentionDays`, `MaxLogFiles`) when `AutoCleanupLogs` is true.
4) **Preflight checks (can be disabled via config)**
   - Admin presence, log writability, disk space probe (non-fatal here), and network reachability: DNS to github.com, HTTP HEAD/GET to GitHub, optional BaseUrl probe, Google 204, Cuco site, ICMP ping (1.1.1.1). `PreflightInternetFailurePolicy` controls warn vs exit on DNS failure.
5) **Performance tweaks (Windows UI/startup)**
   - When enabled: disable OneDrive startup, hide Task View/Search, disable News/Interests and Widgets via registry writes. Skipped when the corresponding `No*` CLI switches are provided.
6) **Mode short-circuits**
   - `-ClearWifiAndExit` runs Wi‑Fi cleanup only.
   - `-DownloadCucoAndExit` and `-DownloadAllAndExit` exit after their respective phases.
7) **Cuco distribution**
   - Optional `CtoolGui.exe` download with primary/secondary source selection (`CucoPrimarySourceKind/Url`, `CucoSecondarySourceKind/Url`, `CucoBinaryPath`). Honors `CucoExistingFilePolicy`, `CucoTargetDir`, and optional confirmation.
8) **Workspace & disk guard**
   - Creates temp workspace under `%TEMP%\AutoDeriva_<rand>` when needed. Enforces `CheckDiskSpace` against `MinDiskSpaceMB` (fatal once install begins).
9) **Optional offline caching**
   - `DownloadAllFiles` fetches the entire manifest payload to the temp workspace (hash verification optional).
10) **Hardware detection**
    - Queries PnP devices (imports `PnpDevice` module when available). Default mode (`ScanOnlyProblemDevices=true`) filters to devices with specific ProblemCodes; alternative modes: `ScanOnlyMissingDrivers` (code 28 only) or `ScanAllDevices`.
    - Collects Hardware IDs (uppercased) and updates stats.
11) **Inventory load & matching**
    - Downloads `exports/driver_inventory.csv` from `BaseUrl + InventoryPath` (cached per run). Matches by intersecting system HWIDs with the semicolon-delimited `HardwareIDs` column; records `InfPath` for each match.
12) **Manifest download & staging**
    - Downloads `exports/driver_file_manifest.csv`. Builds an INF→file lookup from `AssociatedInf` (supports multi-INF packages). For each matched INF, stages all associated files into the temp workspace preserving folder structure.
    - Downloads are concurrent via runspace pool (`Invoke-ConcurrentDownload`) with per-file retry/backoff (`MaxRetries`, `MaxBackoffSeconds`). Dry-run skips network but prepares directories.
13) **Integrity verification (optional)**
    - `VerifyFileHashes` compares staged files to manifest `Sha256`. Modes: `Parallel` (default, runspace pool sized by `HashVerifyMaxConcurrency`) or `Single`. On mismatch, can delete files (`DeleteFilesOnHashMismatch`) and enforce policy (`HashMismatchPolicy`: `Continue`, `SkipDriver`, `Abort`). Mismatching drivers are tracked to influence installation.
14) **Driver install**
    - Installs each staged INF via `pnputil /add-driver ... /install`. Exit codes 0/3010/259 handled (3010 increments reboot counter; 259 treated as already present). Respects hash-mismatch skip policy and `DryRun`.
15) **Post-phases**
    - Temp workspace cleanup. Wi‑Fi profile cleanup if enabled (mode: `SingleOnly` w/ `WifiProfileNameToDelete`, `All`, or `None`; optional confirmation).
    - Statistics and optional section timings printed; log path echoed when available. Exit wait obeys `AutoExitWithoutConfirmation` unless fatal errors + interactive console force a pause.

## Configuration Model
- Layered precedence: hardcoded defaults → `config.defaults.json` (local or fetched) → `config.json` → remote JSON overrides → `-ConfigPath` → CLI switches.
- Key operational toggles (see `docs/configuration.md` for full list):
  - Content sources: `BaseUrl`, `InventoryPath`, `ManifestPath`, `RemoteConfigUrl`.
  - Logging: `EnableLogging`, `AutoCleanupLogs`, `LogRetentionDays`, `MaxLogFiles`, `CleanLogs`.
  - Download behavior: `DownloadAllFiles`, `MaxConcurrentDownloads` (forced to 1 when `SingleDownloadMode`), `MaxRetries`, `MaxBackoffSeconds`, `CheckDiskSpace`, `MinDiskSpaceMB`.
  - Integrity: `VerifyFileHashes`, `DeleteFilesOnHashMismatch`, `HashMismatchPolicy`, `HashVerifyMode`, `HashVerifyMaxConcurrency`.
  - Scan modes: `ScanOnlyProblemDevices` (default), `ScanOnlyMissingDrivers`, `ScanAllDevices`, `ProblemDeviceCodes`, `DeviceScanMode`, `DeviceScanMaxConcurrency`.
  - Wi‑Fi cleanup: `ClearWifiProfiles`, `WifiCleanupMode`, `WifiProfileNameToDelete`, confirmation toggles.
  - UI tweaks: `DisableOneDriveStartup`, `HideTaskViewButton`, `DisableNewsAndInterestsAndWidgets`, `HideTaskbarSearch`.
  - Preflight: `Preflight*` keys for admin/log/disk/network probes and failure policy.
  - Misc: `ShowBanner`, `ShowOnlyNonZeroStats`, `AutoExitWithoutConfirmation`.
- Environment flags: `AUTODERIVA_TEST=1` disables elevation and most interactive/network behaviors; `AUTODERIVA_NOEXIT=1` keeps elevated shells open; `AUTODERIVA_REPOROOT` guides elevation to the repo-local script; BAT launcher adds `AUTODERIVA_BAT_*` helpers for pause/no-exit debugging.

## Driver Data Model & Generation
- Inventory (`exports/driver_inventory.csv`):
  - One row per `.inf`; columns include `InfPath` (repo-relative), `FileName`, `Class`, `Provider`, `Date`, `Version`, `HardwareIDs` (semicolon-delimited). Generated by `scripts/Get-DriverInventory.ps1` (regex-based HWID extraction).
- Manifest (`exports/driver_file_manifest.csv`):
  - One row per file under `drivers/`; columns: `RelativePath`, `Size`, `Sha256`, `AssociatedInf` (single INF or semicolon-delimited list for multi-INF packages). Generated by `scripts/Get-DriverFileManifest.ps1` by walking up to nearest INF(s).
- Regeneration helper: `dev-scripts/Generate-Manifests.ps1` runs both generators and validates missing `InfPath` or orphaned `AssociatedInf` references.
- Installer caching: `Get-RemoteCsv` caches downloads per URL to avoid duplicate fetches in a single run.

## Networking & Downloads
- Default content host: `https://raw.githubusercontent.com/fppinto/autoderiva/main/` (overridable via `BaseUrl`).
- CSV fetches use `Invoke-WebRequest`. Downloads use retry with exponential backoff; concurrent fan-out uses runspaces to honor `MaxConcurrentDownloads`.
- Supports offline prefetch (`DownloadAllFiles`) and integrity checking toggles to balance speed vs safety.

## Hardware Detection & Matching
- Device enumeration via `Get-PnpDevice` (or CIM fallback) filtered by configurable ProblemCodes; `ScanAllDevices` disables filtering.
- Hardware IDs uppercased for matching. Matching is a direct intersection between system HWIDs and inventory `HardwareIDs`; no class/vendor heuristics are applied.
- Unknown device export: `-ExportUnknownDevicesCsv <path>` writes devices with ProblemCode 28 and their HWIDs for external triage.

## Installation & Integrity
- Staging reconstructs repository-relative paths inside the temp workspace to keep INF references valid.
- Hash verification is optional and controlled by manifest `Sha256`; when missing, verification logs a warning and continues.
- Install uses `pnputil` to add drivers to the store and install them; stats tracked for installed/skipped/failed/reboot-required/already-present.
- Dry-run mode preserves flow but skips downloads and pnputil calls, useful for validation/CI.

## Wi‑Fi Cleanup & System Tweaks
- Wi‑Fi profile deletion uses `netsh wlan show/delete profile` with configurable scope and optional prompt. Skipped in test mode.
- Performance tweaks adjust registry keys to disable OneDrive auto-start and hide taskbar UI elements; changes may require Explorer restart/sign-out.

## Cuco Utility Delivery
- Optional download of `CtoolGui.exe` to `CucoTargetDir` (default `Desktop`, resolved to the original user when possible).
- Source selection allows primary/secondary URLs or GitHub-hosted binary fallback derived from `BaseUrl + CucoBinaryPath`.

## Logging, Telemetry & UX
- Console output is sectioned (`Write-Section`) with color-coded statuses; stats printed at end with `ShowOnlyNonZeroStats` defaulting to true.
- File logs mirror console with timestamps and are cleaned based on retention/count settings. Log path is surfaced at completion when available.
- Section timing metrics are recorded between `Write-Section` calls and emitted when durations exceed one second.

## Testing & Tooling
- Pester suites in `tests/` cover syntax, linting, hash verification behaviors, CLI surface, CSV export logic, and preflight toggles (`AUTODERIVA_TEST=1` disables elevation for tests).
- Developer helpers in `dev-scripts/`:
  - `Build-Check.ps1` → format, lint, test chain.
  - `Format-Check.ps1`, `Lint-Check.ps1`, `Test-Check.ps1` → individual phases.
  - `Generate-Manifests.ps1` → rebuild inventory/manifest with validation.
  - Additional dev utilities for targeted test runs and release prep.
- `pester-result.json` captures prior test output and can be regenerated via the above scripts.

## Operational Considerations
- Requires administrative rights for driver install; script self-elevates unless suppressed for tests.
- Network access to the configured `BaseUrl`, GitHub, and optional Cuco host is expected unless running in prefetch/offline mode.
- Ensure adequate disk space (`MinDiskSpaceMB`, default 3072 MB) on the staging drive.
- Large `drivers/` tree (hundreds of packages); regenerating manifests can be time-consuming.
- Default scan mode targets only problem devices; use `-ScanAllDevices` for full remediation scenarios or `-ScanOnlyMissingDrivers` to restrict to ProblemCode 28.
